# Документация интерфейса MiniPixel

Документ описывает текущий экран управления и обработку касаний в `Draw_interface` из `lib/screen_classes.hpp`. Важно: кнопки уже отображаются и распознаются, но их производственные действия пока не реализованы.

## Экран управления

Интерфейс рисуется на основном дисплее `tft_main`. В `setup()` он инициализируется и устанавливается поворот экрана, затем вызывается:

```cpp
screen.drawDashboardLayout();
```

Метод очищает экран, рисует заголовок `MiniPixel Interface Ver 0.1` и три кнопки:

| ID | Надпись | Текущее значение |
|---:|---|---|
| 0 | START | Команда запуска пока не реализована |
| 1 | STOP | Команда остановки пока не реализована |
| 2 | DEBUG | Команда отладки пока не реализована |

Размер каждой кнопки — 140 × 70 пикселей, промежуток между кнопками — 10 пикселей. По умолчанию группа центрируется по горизонтали и размещается на `y = 220`. Положение можно изменить аргументами `drawDashboardLayout(buttonsX, buttonsY)`. Значение `buttonsX = -1` означает автоматическое центрирование.

При рисовании метод сохраняет координаты и ID кнопок в `active_buttons`. Проверка касания использует эти координаты, поэтому сначала нужно вызвать `drawDashboardLayout()`, а затем опрашивать кнопки.

## Получение нажатий

В `loop()` вызывается:

```cpp
uint8_t btn = screen.button_istouched();
```

Метод читает координаты касания с дисплея и возвращает:

| Возвращаемое значение | Значение |
|---:|---|
| `0` | Нажата START |
| `1` | Нажата STOP |
| `2` | Нажата DEBUG |
| `254` | Касания нет |
| `255` | Касание есть, но оно вне кнопок |

Сейчас `loop()` выводит ID нажатой кнопки в Serial. Само нажатие пока не запускает/останавливает показ и не включает отдельный режим отладки.

Пример обработки результата:

```cpp
const uint8_t button = screen.button_istouched();

switch (button) {
    case 0:
        // TODO: запустить показ
        break;
    case 1:
        // TODO: остановить показ
        break;
    case 2:
        // TODO: выполнить действие отладки
        break;
    case 254:
        // Касания нет — обычное состояние
        break;
    case 255:
        // Касание вне кнопок
        break;
}
```

Необязательно обрабатывать `254` и `255`, если приложению нужны только нажатия на кнопки. Проверка `button < 254` выбирает только ID действующих кнопок.

## Классы

### `LGFX`

Универсальная конфигурация LovyanGFX для дисплея ILI9488 и, если передан действительный `touch_cs`, тачскрина XPT2046. В конструктор передаются SPI-хост, пины и признак общей шины. Экземпляры дисплеев создаются отдельно; класс интерфейса получает ссылку на нужный экземпляр.

Конструктор `LGFX(...)` настраивает SPI-шину, панель ILI9488 и параметры её пинов. Если `touch_cs >= 0`, дополнительно настраивает XPT2046 на те же пины SPI и переданный SPI-хост.

### `Draw_interface`

Обёртка интерфейса с двумя основными методами:

- `drawDashboardLayout(buttonsX, buttonsY)` — рисует экран и запоминает геометрию кнопок.
- `button_istouched()` — возвращает ID нажатой кнопки либо специальное значение `254`/`255`.
- Конструктор `Draw_interface(display_ref)` — сохраняет ссылку на уже созданный дисплей, которым будет управлять интерфейс.

Пример текущей связи объектов в `src/main.cpp`:

```cpp
LGFX tft_main(/* параметры основного дисплея */);
Draw_interface screen(tft_main);
```

### `Mask_Screen`

Класс второго дисплея, не обрабатывает кнопки интерфейса. Предоставляет методы очистки, вывода BMP из буфера и прямого чтения BMP с SD-карты.

- Конструктор `Mask_Screen(display_ref)` — сохраняет ссылку на дисплей маски.
- `clear()` — очищает экран чёрным цветом.
- `drawFromBuffer(image_buffer, size)` — передаёт LovyanGFX BMP-данные, уже находящиеся в памяти.
- `drawDirectlyFromSD(filepath)` — вызывает LovyanGFX для чтения BMP с SD-карты и вывода с координат `0, 0`.

## Функции в `src/main.cpp`

### `find_name()`

Ищет в корне SD-карты первую обычную папку, внутри которой найден файл с расширением `.png`. Системные папки `System Volume Information` и скрытые папки, начинающиеся с `.`, пропускаются.

- При успехе возвращает имя найденной папки типа `String`, убирая начальный `/`, если он есть.
- Если корень карты открыть не удалось или подходящая папка не найдена, возвращает пустую строку. Причину также выводит в Serial.
- Порядок выбора — порядок, в котором файловая система возвращает элементы; функция не выбирает папку по заданному имени.

В `setup()` результат сейчас сохраняется в `modelname`, но дальнейшего использования у этой переменной пока нет. Функция ищет `.png`, тогда как `Mask_Screen::drawDirectlyFromSD()` сейчас выводит BMP; это разные части текущей заготовки.

### `Core0TaskManager(void *pvParameters)`

Точка входа фоновой задачи FreeRTOS, закреплённой при создании за ядром 0. Аргумент `pvParameters` предназначен для передачи указателя на `Mask_Screen`; функция приводит его к `Mask_Screen*`.

Сейчас задача не выполняет команд маски: переменная указателя и `frame_num` пока не используются, а бесконечный цикл только делает задержку `vTaskDelay(pdMS_TO_TICKS(100))`, уступая процессорное время. В `setup()` задача создаётся с `nullptr` в качестве параметра, поэтому указатель на глобальный объект `mask` ей сейчас не передан.

### `setup()`

Вызывается один раз при запуске устройства. Сейчас функция:

1. Запускает Serial.
2. Инициализирует основной экран и устанавливает его поворот.
3. Запускает SPI и SD-карту, выводит результат инициализации в Serial.
4. Вызывает `find_name()` и сохраняет результат.
5. Инициализирует экран маски и рисует интерфейс.
6. Создаёт задачу `Core0TaskManager` с приоритетом `1`, стеком `4096` и закреплением за ядром `0`.

Если создание задачи будет неуспешным, текущий код отдельно это не обрабатывает.

### `loop()`

Arduino вызывает эту функцию повторно после `setup()`. Она опрашивает тачскрин через `screen.button_istouched()`. Для ID кнопок `0`, `1` и `2` выводит сообщение в Serial и делает короткую задержку для простого подавления повторных срабатываний. Реальные команды START/STOP/DEBUG пока не вызываются.

## Текущее разделение дисплеев и задач

- Основной дисплей и тачскрин используются интерфейсом из `loop()`.
- Дисплей маски и SD-карта предназначены для работы с изображениями.
- В `main.cpp` задача `Core0TaskManager` закреплена за ядром 0, но пока не выполняет команд маски. Нажатия интерфейса ей сейчас не передаются.

Когда действия кнопок будут реализованы, сначала можно оставить обработку в `loop()`. Если выполнение команды маски станет долгим, `loop()` сможет передавать задаче маски короткую команду — например, ID кнопки или отдельное состояние — вместо выполнения длительной работы прямо в обработчике касания.

## Где менять интерфейс

- Пины дисплеев и тачскрина: `lib/pin_config.h`.
- Рисование кнопок и распознавание касаний: класс `Draw_interface` в `lib/screen_classes.hpp`.
- Инициализация дисплеев, опрос кнопок и поведение команд: `src/main.cpp`.
